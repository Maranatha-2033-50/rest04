# 02. AI 학습 엔진 코어 루프 완동 & 통합 생태계 고도화

작업 기간: 2026-06-11 ~ 2026-06-12
대상 레포: 에듀포커스(`rest04`) · 스터디메이트(`ai-learning-platform`)

## 목표
1주차 펀널·인프라 공사를 마무리하고, 스터디메이트의 핵심 학습 루프
(`대시보드 카드 → 시험룸 → 채점/저장 → 리뷰`)를 IELTS를 마스터 도메인으로 완동시킨 뒤
자격증·교과까지 전 카테고리로 이식한다. 병행하여 에듀포커스 랜딩의 다국어·디자인 마감을 끝낸다.

## 에듀포커스(rest04) 작업
- **크로스 도메인 SSO 브릿지**: `login_status=success` URL 파라미터 + `ef_logged_in` localStorage로
  스터디메이트 로그인 상태를 랜딩 헤더에 반영. Slack 상담 알림 웹훅, `/auth/signout` GET 지원.
- **전면 다국어화(EN) 마감**: Home(AIBand/LatestVideos/Notices)·AIApp·Videos·Footer 및
  `site.js`의 company·notices·videoTopics(라벨 6 + 영상 72) 전량을 `{ko,en}` + `t()`로 전환.
  푸터 주소 영문 표기, 정책 링크·패밀리사이트 다국어화.
- **히어로 디자인 고도화**: 슬라이드 3종 개별 이미지 매핑 + 전 이미지 grayscale + brand-royal
  듀오톤(mix-blend-multiply) 오버레이로 흰 텍스트·파란 버튼과의 색상 충돌 해소. 좌측 가독성
  그라디언트. 서비스/영상 카드는 hover 시 원본 컬러 노출(grayscale-0 + 오버레이 opacity-0).
  히어로 도트 패턴 제거.

## 스터디메이트(ai-learning-platform) 작업 — 코어 엔진
- **주관식 AI 루브릭 채점 엔진**: `/api/grade-subjective` — 호출 전 `weakness_stats`를 조회해
  취약점 컨텍스트로 주입, 공식 IELTS/DELF 루브릭 시스템 프롬프트 + `response_format: json_object`
  강제. **API 키 부재 시 고품질 mock 폴백**으로 키 없이도 전 플로우 동작.
  `lib/ai/subjective.ts`. 마이그레이션 003: `user_attempts.feedback`(jsonb) + `SUBJECTIVE` 세션 타입.
- **학생/강사 이원화 피드백**: 학생용 `SubjectiveFeedback.tsx`(Overall Score 그라디언트 배지 +
  스킬 바 + 빨강 취소선/초록 밑줄 첨삭 + 아코디언 교정 이유). 강사용 `StudentReport`에
  `tutor_guide` 마크다운 `[AI 코칭 백서]` 강사 전용 카드 추가.
- **IELTS 코어 루프 완동**: 마이그레이션 004 — IELTS Academic Reading(약 700단어 지문 +
  객관식 2 + 단답 1) + Writing Task 2 에세이 시드. `lib/exams.ts` `buildExams`로 시드 문항을
  모의고사 카드로 동적 변환. Reading → `DiagnosticTestRoom`, Writing → `EssayTestRoom`(작성 →
  grade-subjective → SubjectiveFeedback) 라우팅.
- **자격증·교과 전면 개통**: 통합 `/student/dashboard`에 per-chapter 모의고사 카탈로그(전 카테고리
  공용). 마이그레이션 005 — 정보처리기사 객관식 3 보강, 고등 수학 2·고등 영어 1(SCHOOL) 시드.
  `RelativePerformance` 하드코딩(`SYSTEM_AVERAGE`) 제거 → `category_skill_averages` 뷰 실집계로 교체.
- **지문(passage) 아키텍처 수리**: 문항 전환 시 좌측 지문이 사라지던 버그를, `universal_questions.passage`
  전용 컬럼 신설(동일 세트 전 Row에 지문 100% 복사) + `DiagnosticTestRoom`이 첫 지문을 useMemo로
  캐싱해 좌측 고정(Pinned) 렌더하도록 구조적으로 해결.
- **실전 오답노트 리뷰 모드**: 제출 후 `isReviewMode` 전환 — ✅정답/❌오답 배지, 정답 선택지=초록·
  오답 선택=빨강, 단답형 내답안 vs 정답 대조, 문항 하단 인디고 카드에 `explanation`(한글 해설)
  마크다운 렌더. `explanation`만 있으면 전 카테고리 공용 동작.

## 평가
- **성과**: 스터디메이트가 "데이터 → 시험 → 채점 → 취약점 분석 → 리뷰/플래너"의 닫힌 루프를
  실데이터로 처음 완주. IELTS에서 검증한 구조(카드→방→저장→리뷰)를 추상화(`buildExams`,
  passage 컬럼, explanation 공용 리뷰)해 자격증·교과로 무리 없이 확장. 채점 엔진은 키 부재
  상황까지 고려한 mock 폴백으로 운영 리스크를 선제 차단.
- **리스크/미결**:
  - 003·004·005 마이그레이션은 **Supabase SQL Editor 수동 실행** 필요(미실행 시 컬럼·시드·뷰 부재).
  - OpenAI 키 비활성 — 주관식 채점은 현재 mock 반환. 키 발급 후 실호출 검증 필요.
  - 진단 쿼리가 `select('*')`로 정답(`answer`)을 클라이언트에 노출(리뷰 모드는 이를 활용하나,
    응시 중 보안 관점에서는 서버 채점과 별개로 개선 여지).
  - 컴활·한능검(002 시드)은 `explanation` 공백 → 리뷰 해설 카드 생략. 해설 보강 시드 필요.
  - 백엔드 3중 경로(Next API routes vs Edge Functions vs 직접 쿼리) 단일화 미결.
